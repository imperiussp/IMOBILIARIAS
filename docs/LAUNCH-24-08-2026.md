## Bloqueios obrigatórios antes de produção

### 1. Contas reais de homologação

O banco ainda está com `0` usuários em `auth.users`. Criar de forma controlada:

1. uma conta owner/admin para a Imobiliária A;
2. uma segunda conta owner/admin para a Imobiliária B;
3. uma conta de corretor vinculada a uma delas.

Não criar usuários diretamente em `auth.users` por SQL. Usar o fluxo oficial de Auth da aplicação/Supabase.

### 2. Teste de acesso

Validar com as contas reais:

- cadastro/primeiro acesso;
- login;
- persistência de sessão;
- logout;
- recuperação de senha;
- usuário sem vínculo não entra no painel de tenant;
- corretor acessa somente os recursos permitidos.

Registrar `auth_login` e `broker_permissions` somente após esse teste.

### 3. Teste de isolamento entre duas imobiliárias

Com A e B autenticadas:

- A não lista imóveis, leads, usuários, documentos ou fotos de B;
- B não lista dados de A;
- tentativa de update por ID de outro tenant deve afetar zero linhas/falhar;
- corretor só enxerga a imobiliária ativa/vínculos permitidos;
- domínio/hostname de A nunca retorna imóvel de B.

Registrar `tenant_isolation_functional` somente após o teste real.

### 4. Imóvel e fotos

Na Imobiliária A:

- criar imóvel em rascunho;
- editar;
- publicar;
- alterar status;
- arquivar/exclusão lógica;
- subir JPEG/PNG/WebP;
- definir capa;
- alterar ordem;
- excluir foto;
- confirmar que URL pública/signed URL não permite atravessar tenant.

Registrar `property_crud` e `photo_storage` após aprovação.

### 5. Lead e CRM

Com um imóvel publicado e hostname válido:

- enviar lead pelo detalhe do imóvel;
- confirmar `agency_id` e `property_id` corretos;
- confirmar roteamento para corretor quando houver;
- alterar etapa/status;
- classificar contato;
- criar nota;
- criar/concluir follow-up;
- confirmar histórico/timeline.

Registrar `lead_crm` após aprovação.

### 6. Domínio e TLS

Associar `imoveis.lenoy.com.br` ao projeto Vercel correto e configurar o DNS conforme instrução emitida pela Vercel.

Só registrar `platform_domain_pointed`, `tls_valid` e `dns_tls` quando:

- o domínio constar no projeto correto;
- resolver para a Vercel;
- HTTPS estiver válido;
- home e `/api/health` responderem pelo domínio oficial.

### 7. Backup e recuperação

Confirmar no Supabase a estratégia real disponível para o projeto (backup/PITR conforme plano) e documentar o procedimento de restauração. Não marcar apenas por existir plano escrito.

Registrar `backup_strategy_verified` e `backup_recovery` somente com evidência operacional.

### 8. Manutenção programada

A Edge Function `platform-maintenance` exige `PLATFORM_MAINTENANCE_SECRET`. Não criar cron sem segredo.

Configurar um scheduler seguro (Supabase cron/net ou scheduler externo apropriado) que envie `POST` para a função com o header secreto. Depois executar uma vez e confirmar registro em `platform_maintenance_runs` com `success=true`.

Registrar `maintenance_cron_configured`, `maintenance_success_verified` e `maintenance_cron` somente após execução real.
